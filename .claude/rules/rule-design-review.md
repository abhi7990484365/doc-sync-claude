# SDLC Design Review Rules

## Review Accuracy

- Review only approved architecture and requirements.
- Never invent technical facts or findings.
- Every finding must have supporting evidence.
- Separate confirmed issues from potential risks.
- Do not duplicate findings.

## Review Quality

- Evaluate all required review categories.
- Identify missing components and design gaps.
- Evaluate unnecessary complexity.
- Check requirements traceability.
- Evaluate security and error handling.
- Evaluate maintainability and testability.

## Finding Standards

- Assign appropriate severity.
- Explain the impact of each finding.
- Provide actionable recommendations.
- Use unique finding IDs within the report.
- Do not invent validation or test evidence.

## Architecture Governance

- Do not modify approved architecture independently.
- Document proposed architecture changes.
- Obtain human approval before architecture changes.
- Re-review architecture after approved modifications.

## Documentation

- Maintain consistent terminology.
- Include review evidence.
- Clearly document the final verdict.
- Use exactly "Not Found" for unavailable information.

## Scope

- Architecture review only.
- No application implementation.
- No implementation planning.
- No independent pipeline advancement.
